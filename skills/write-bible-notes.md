# 读经札记

## 何时触发

当 Tomz 说「读经札记」「写一篇读经札记」「发读经札记」等近似表达时，默认使用本技能。

## 目标

保留真实的阅读、联想和生活观察，让文章从经文出发，也回到经文；不把它写成神学论文、讲章模板或灵修鸡汤。

## 核心结构

默认遵循：

**经文 → 阅读时自然联想到的人和事 → 再回到经文**

这是一条叙事和思考路径，不要求机械分成三个小标题。

## 写作原则

1. 从真实阅读出发，不为了文章完整性发明「那天……」「我忽然想起……」等不存在的场景。
2. 不硬做宏大、完整的神学总结；有疑问、张力和未完成感都可以保留。
3. 不写成安慰式鸡汤，不强行给痛苦、失败或关系安排一个漂亮结论。
4. 现实中出现的人，不擅自补全他们的心理、动机、人物弧光或因果故事。
5. 允许真实感受存在，例如喜欢、吸引、好感、困惑，但不急着给关系或情绪下定义。
6. 如果一段生活联想和经文本身没有真正连接，就宁可删掉，不为了「有故事」而留下。
7. 结尾优先回到经文留下的问题、视角或安静的余味，而不是喊口号。

## 协作署名

读经札记默认是共同写作关系，可使用项目现有的共同作者约定，例如：

- `tomz | mira`
- `writingMode: co-authored`
- `writtenBy: mira`
- `reviewedBy: tomz`

实际发布前以目标仓库当前 frontmatter 约定为准。

## 发布位置

当前「读经札记」发布到主站：

- 站点：`https://tomz.io`
- 仓库：`dangjingtao/tomz-io`
- 内容目录：`src/pages/blogs/bible-notes/`
- 分组：`读经札记`

不要因为 Mira 参与写作而误发到 `mira.tomz.io`。

## 检查点

- 是否能指出文章真正从哪段经文出发。
- 生活内容是否来自真实信息，而不是模型补写。
- 是否避免过度解释现实人物。
- 是否保留必要的怀疑、张力和留白。
- 发布时是否进入 `tomz-io` 主站。

## 安全与事实边界

- 不把未明确允许公开的私人身份、聊天原文或敏感关系细节写进公开仓库。
- 公开文章需要什么信息，以用户明确提供和确认的内容为界。
